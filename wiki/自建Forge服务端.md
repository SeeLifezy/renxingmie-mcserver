# 自建 Forge 服务端

本页说明：**不使用整合包自带的默认 Forge 服务端**，改用你自己安装的 Forge 来运行本整合包该怎么做。

典型场景：

- 想升级到更新的 Forge 小版本（如 47.3.3 → 47.4.x）
- 使用服务器托管面板，面板只支持自己安装的 Forge
- 已有一套自己的 Forge 服务端环境，想把整合包内容迁移过去

---

## 重要前提：版本必须匹配

Forge 版本与 Minecraft 版本严格对应，**不能混用**。各服务端对应关系：

| 服务端 | MC 版本 | 自带 Forge | 可用 Forge 范围 |
|--------|---------|-----------|----------------|
| 樱之城幸运方块 | 1.20.1 | 47.3.3 | 47.x.x（建议 47.3.0+） |
| 夏日清凉幸运方块 | 1.20.1 | 47.3.x | 47.x.x（建议 47.3.0+） |
| 幸运空岛竞技 | 1.20.1 | 47.3.5 | 47.x.x（建议 47.3.0+） |
| 脚下随机生成幸运方块 | 1.20.1 | 47.3.3 | 47.x.x（建议 47.3.0+） |
| 中秋幸运方块 | 1.19.2 | 43.5.0 | 43.x.x |
| 幸运方块（基础版） | 1.16.5 | 36.2.42 | 36.x.x |

> 提醒：模组是按特定 Forge 版本编译的。升级 Forge 小版本一般兼容，但**跨大版本升级（如 1.20.1 → 1.20.4）会导致模组全部失效**，请勿尝试。

---

## 步骤一：下载并安装 Forge 服务端

1. 前往 Forge 官方下载站：<https://files.minecraftforge.net/net/minecraftforge/forge/>
2. 选择对应 MC 版本（如 `1.20.1`），下载 **Installer**（安装器 jar）
3. 新建一个空目录（例如 `my-forge-server/`），将安装器放入
4. 在该目录执行安装：

```powershell
# Windows（需要 Java 17）
java -jar forge-1.20.1-47.4.0-installer.jar --installServer
```

```bash
# Linux / macOS
java -jar forge-1.20.1-47.4.0-installer.jar --installServer
```

安装完成后会生成：

- `libraries/` —— 全新的 Forge 运行库（这是你自己的 Forge，与整合包自带的不同）
- `run.bat` / `run.sh` —— 新版启动脚本
- `user_jvm_args.txt` —— JVM 参数配置文件（新版 Forge 用它管理内存）

---

## 步骤二：迁移整合包内容

从解压后的整合包目录中，把以下内容复制到你的 Forge 服务端目录：

### 必须复制

| 目录/文件 | 说明 |
|-----------|------|
| `mods/` | 全部模组（含 `.jar.disabled` 文件也保持原样复制） |
| `config/` | 模组配置（幸运方块掉落、结构等核心数据都在这里） |
| `addons/` | 幸运方块扩展包（如有） |
| `world/` 或 `重置地图/` | 世界存档 / 初始地图备份 |
| `server.properties` | 服务器配置 |
| `eula.txt` | EULA 协议（`eula=true`） |
| `server-icon.png` | 服务器图标（如有） |

### 按需复制

| 目录/文件 | 说明 |
|-----------|------|
| `tacz/` | 枪械包数据（樱之城服务端） |
| `mod_data/` | 模组数据（部分服务端有） |
| `ops.json` / `whitelist.json` | OP 与白名单名单 |
| 玩前必看等 txt | 说明文件 |

### 不要复制

| 目录 | 原因 |
|------|------|
| `libraries/`（整合包自带的） | 会覆盖你刚安装的新 Forge，**这是本页要避免的** |
| `logs/` | 无用的旧日志 |
| `run.bat` / `run.sh`（整合包自带的） | 指向旧 Forge 路径，改用你新装的 Forge 生成的脚本 |

---

## 步骤三：启动

使用**你自己安装的 Forge 生成的启动脚本**（步骤一安装时生成的那个）：

### 新版 Forge（1.17+）启动方式

```powershell
# Windows：双击 run.bat，或命令行执行
.\run.bat
```

```bash
# Linux / macOS
./run.sh nogui
```

### 内存调整（新版方式）

新版 Forge 通过 `user_jvm_args.txt` 配置内存，编辑该文件：

```conf
-Xmx4G
-Xms4G
```

> 旧版整合包的 `run.bat` 是 `java -Xmx4G -Xms4G @libraries/...` 一行式；新装的 Forge 请改用 `user_jvm_args.txt`，不要直接改 `run.bat`（部分新版脚本会覆盖手改内容）。

首次启动会下载依赖、生成世界文件，耗时较长属正常现象。

## 常见问题

### Q: 启动报模组加载错误 / 缺失依赖

**A:** 检查 `mods/` 是否完整复制（包括 `.disabled` 文件），以及 Forge 版本是否过低。建议 Forge 版本不低于整合包自带版本。

### Q: 幸运方块内容缺失（掉落物不对）

**A:** `config/lucky/`、`addons/lucky/` 未复制完整。这两个目录包含幸运方块的核心掉落与结构数据，必须完整迁移。

### Q: 世界没有加载出来 / 回到默认出生点

**A:** 确认 `world/` 目录位置正确（与服务端根目录同级）。使用重置地图的话，参考 [启动指南 - 重置世界](启动指南#重置世界)。

### Q: 空岛竞技服务端结构不一样？

**A:** 幸运空岛竞技使用 ServerPackCreator 标准结构（`start.bat` / `start.sh`），但迁移逻辑相同：复制 `mods/`、`config/`、`world/`、`server.properties` 到你的新 Forge 目录即可。

---

## 回退方案

如果自建 Forge 运行不稳定，随时可以回到整合包自带环境：重新解压一次 ZIP 包，把迁移过去后更新的 `world/`（如有新进度）复制回来即可。整合包自带环境经过作者测试，兼容性最有保障。
